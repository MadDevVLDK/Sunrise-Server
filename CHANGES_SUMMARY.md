## Логика работы WebSocket

### Подписка на чаты
1. При загрузке страницы получаются все ID чатов пользователя через API
2. Инициализируется WebSocket соединение
3. Для каждого чата создаётся подписка на топик `/user/queue/chats/{chatId}`
4. Подписки сохраняются в Set для избежания дублей

### Обработка обновлений
1. **Новое сообщение** - чат перемещается в начало списка
2. **Обновление закладки (isPinned)** - чат перемещается в начало списка
3. **Остальные действия** - игнорируются (если чат не загружен на экран)

## Логика пагинации

### Загрузка чатов
1. При загрузке страницы загружаются первые **20 чатов**
2. Сервер возвращает `nextCursor` если есть ещё чаты
3. При скролле списка до конца вызывается загрузка следующей партии

### Запрос к API
```javascript
const result = await API.getUserChats(
  null,           // isPinnedCursor
  null,           // lastMsgIdCursor  
  cursor,         // chatIdCursor (null для первой загрузки)
  20              // limit
);
```

## Типы данных

### Структура чата в массиве
```javascript
{
```

## Возможные проблемы и решения

### Если WebSocket не подключается
- Убедитесь, что сервер правильно настроил WebSocket endpoint
- Проверьте URL в `getApiPath('/ws')`
- Смотрите логи сервера для ошибок

### Если чаты не загружаются
- Проверьте в DevTools Network tab запрос к `/api/chats/ids`
- Убедитесь, что токен авторизации корректно передаётся
- Смотрите логи в консоли браузера

### Если скролл не работает
- Убедитесь, что высота `.chats-list` достаточна для скролла
- Проверьте, что высота родительского контейнера правильно установлена
